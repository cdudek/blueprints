# i18n

Apply [core i18n](../../core/references/i18n.md) and [copy](../../core/references/copy.md). Use next-intl from the first screen, English by default, with one routing and message-loading setup.

## Rules

- **NEXT-I18N-1 Centralize routing and loading.** `src/i18n/` owns the supported locales, request configuration and localized navigation helpers. Locale pages live under `app/[locale]/`; the request interceptor uses that same configuration. Validate the locale before loading a catalog. Use the APIs for the installed next-intl and Next.js releases.
- **NEXT-I18N-2 Type the source catalog.** `messages/en.json` defines the key shape for the other catalogs. User-visible JSX text and attributes such as alt text, titles, placeholders and accessible labels come from messages. Module components use their namespace or receive copy through props; `ui/` only receives copy through props. Error codes map to localized messages at the delivery boundary.
- **NEXT-I18N-3 Send only the browser messages it needs.** Translate in Server Components where possible and pass the relevant messages to client providers. Do not make the entire app a client component to read translations. Format dates, numbers and plurals with explicit locale and time-zone policy so the server and first browser render agree.
- **NEXT-I18N-4 URLs and metadata share the locale model.** Use the central navigation helpers for links and redirects. Canonicals, alternates, sitemaps and sign-in return paths use the same locale rules; see [SEO](seo.md). Changing a locale prefix is a public URL migration under core, not a cosmetic refactor.

## How to apply

Set up routing and typed catalogs before adding the first page. Give each capability a message namespace and add its empty, loading, error and success states together. Adding a locale adds its catalog, routing entry and metadata checks in the same change.

Changing later: rename a key through all locales and callers together. Keep stored business values and event names independent of localized labels.

## Checks

- Automatic: catalog key parity, TypeScript key checks, missing-message failures and a guard for hard-coded visible text and attributes.
- Automatic: Playwright covers locale switching, deep links, localized metadata and a server-to-client render without hydration mismatch.
- Review: translation quality, time-zone policy, text expansion and accessible labels in each supported locale.

## Mistakes to avoid

- A translated page with English validation errors or email subjects.
- Direct `next/link` usage that bypasses the chosen locale policy.
- Browser messages that accidentally include server-only configuration.
